# R9700 vLLM ROCm 10 Reproducible Baseline

This document is the reproducibility boundary for the InnerChispa R9700 Hyperloom experiment. It records what is measured on the local AMD node and what is still experimental.

## Runtime Snapshot

Use the manifest collector on the AMD node without restarting vLLM:

```bash
python3 scripts/r9700_runtime_manifest.py \
  --base-url http://127.0.0.1:8000/v1
```

The manifest records:

- Docker image/tag and selected vLLM container.
- `torch.__version__`, `torch.version.hip`, Python, and vLLM version from inside the container.
- `/v1/models` model id, root, and `max_model_len`.
- Sanitized vLLM startup process command.
- `rocm-smi --json` device identity and telemetry.
- AWQ observability notes.
- A stable SHA-256 hash of the manifest payload.

Current observed startup command is the resident service pattern:

```bash
docker run --rm --name inneros-vllm-canary-rocm10 \
  --device=/dev/kfd --device=/dev/dri --group-add video --ipc=host --network host \
  -v /home/rlopez/inneros/inneros_core/var/local_models:/models \
  rocm/vllm:rocm10.0.0_ubuntu24.04_py3.14_pytorch_2.12.0_vllm_0.27.0 \
  python3 -m vllm.entrypoints.openai.api_server \
    --model /models/QuantTrio__Qwen3-Coder-30B-A3B-Instruct-AWQ \
    --served-model-name QuantTrio/Qwen3-Coder-30B-A3B-Instruct-AWQ \
    --host 127.0.0.1 --port 8000 \
    --max-model-len 8192 --gpu-memory-utilization 0.82 \
    --dtype float16 --trust-remote-code
```

## AWQ Boundary

The model id and local path indicate an AWQ quantized model. That alone does not prove which vLLM AWQ kernel/backend is active for `gfx1201`.

Before publishing any AWQ-specific optimization claim, collect one of:

- vLLM startup logs explicitly naming the AWQ backend.
- A profiler trace that identifies the active attention/quantization kernels.
- A controlled A/B run with the exact startup flag changed in a benchmark window.

`VLLM_USE_TRITON_AWQ=1` must not be documented as required for this stack unless the current ROCm 10/vLLM runtime proves it.

## Benchmark Policy

The live service can be exercised without restarting vLLM, but multi-spawn experiments can saturate the shared GPU. The default harness mode therefore writes a plan and blocks live execution until an explicit benchmark window exists.

```bash
python3 scripts/r9700_multispawn_harness.py --spawn-count 5
```

Live mode is intentionally explicit:

```bash
python3 scripts/r9700_multispawn_harness.py \
  --spawn-count 5 \
  --execute \
  --output docs/evidence/r9700_multispawn_live.json
```

The auditor fails closed on missing evidence paths, duplicate evidence paths, non-zero return codes, invalid metrics, `NaN`, or incomplete summaries.
